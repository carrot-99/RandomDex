# RandomDex 設計書

Nov 8, 2026 · @にんじん

## 1. 概要

RandomDexは、ポケモン（全国図鑑1028種＋タイプや種族値が変わるフォルム）を1体ランダムに抽選し、図鑑情報を表示するスマホ向けWebアプリである。GitHub Pagesで無料公開し、利用者は作成者本人のみを想定する。

将来はONE PIECEなど他作品のキャラクターも同じ仕組みで抽選できるよう、作品に依存しないデータ構造で作る。

**v1でやること**

- STARTで抽選演出開始、STOPで結果確定
- 結果に図鑑No・名前・分類・タイプ・高さ・重さ・種族値・図鑑説明文・登場ソフトを表示
- 見た目だけの違い（オス・メス、アンノーン、ビビヨン等）はスワイプ／タップで画像を切り替え
- 世代・タイプの複数選択による絞り込み

**v1でやらないこと**

- メガシンカ、キョダイマックス等の戦闘中のみの姿
- 抽選履歴（今後検討）
- 他作品のデータ投入（仕組みだけ用意）

## 2. 決定事項一覧

| 項目 | 決定内容 |
| --- | --- |
| アプリ名 | RandomDex（リポジトリ名も同じ） |
| ホスティング | GitHub Pages（新規リポジトリ、`carrot-99.github.io/``R``andomDex/`） |
| 公開範囲 | 作成者のみ。URLを広めない運用＋noindex。完全非公開ではない |
| 主な利用端末 | スマホ |
| 対象 | 全国図鑑1028種（Pokémon HOME準拠の番号） |

| 画像切り替え扱い | 見た目のみの違い（オス・メス、アンノーン、ビビヨン等） |
| 除外 | メガシンカ、キョダイマックス等の戦闘中のみの姿 |

## 3. システム構成

サーバーもDBも持たない静的サイトとする。データは事前にスクリプトでJSONファイル化してリポジトリに置き、ブラウザが起動時に1回読み込んで抽選・絞り込みをすべて端末内で行う。

1. 開発者がローカル（Claude Code）でデータ生成スクリプトを実行し、PokeAPIから取得
2. 作品ごとのJSONファイルを生成してリポジトリにコミット
3. GitHub Pagesが静的ファイルとして配信
4. スマホのブラウザがJSONを読み込み、抽選・表示を端末内で実行

**技術スタック**

- 画面：HTML／CSS／JavaScript（フレームワーク・ビルド工程なし。GitHub Pagesにそのまま置ける構成）
- データ生成：Node.js（18以上、標準のfetchを使用）
- 画像：PokeAPIが公開している画像URLを直接参照（リポジトリには画像を保存しない）

**ディレクトリ構成（案）**

```
RandomDex/
├── index.html
├── css/
│   └── style.css
├── js/
│   ├── app.js          # 起動、作品の読み込み、画面遷移
│   ├── roulette.js     # 抽選と演出
│   ├── filter.js       # 絞り込み（設定駆動）
│   └── detailView.js   # 結果表示（設定駆動）
├── works/
│   └── pokemon/
│       ├── workConfig.json  # 表示項目・絞り込み項目の定義
│       └── items.json       # キャラデータ本体
└── scripts/
    └── pokemon/
        └── buildItems.mjs   # PokeAPI → items.json
```

ファイル名・変数名はキャメルケースで統一する。

## 4. データ設計

データは作品ごとに「設定ファイル（workConfig.json）」と「キャラデータ（items.json）」の2つに分ける。画面のコードは作品固有の項目名を持たず、設定ファイルに従って表示・絞り込みを行う。

### 4.1 items.json の共通構造

全作品で共通の項目と、作品ごとに自由な `attributes` に分ける。

| 項目 | 型 | 内容 |
| --- | --- | --- |
| id | 文字列 | 一意なID。例：`0026-alola` |
| name | 文字列 | 表示名。例：ライチュウ |
| subName | 文字列 | フォルム名など。例：アローラのすがた（なければ空） |
| images | 配列 | `{ label, url }` の配列。先頭が既定画像、2件目以降がスワイプで切り替える見た目違い |
| attributes | オブジェクト | 作品固有の情報。キーは workConfig.json で参照する |

### 4.2 ポケモンの attributes

| キー | 型 | 内容 |
| --- | --- | --- |
| dexNo | 数値 | 全国図鑑No |
| category | 文字列 | 分類。例：ねずみポケモン |
| types | 文字列の配列 | タイプ（1〜2個） |
| heightM | 数値 | 高さ（m） |
| weightKg | 数値 | 重さ（kg） |
| stats | オブジェクト | hp, attack, defense, spAttack, spDefense, speed, total |
| flavorText | 文字列 | 図鑑説明文 |
| flavorTextGame | 文字列 | 説明文の出典ソフト名 |
| games | 文字列の配列 | 登場ソフト |
| generation | 数値 | 世代（1〜9）。フォルムはそのフォルムが登場した世代 |

### 4.3 データ例

```json
{
  "id": "0026-alola",
  "name": "ライチュウ",
  "subName": "アローラのすがた",
  "images": [
    { "label": "通常", "url": "https://..." }
  ],
  "attributes": {
    "dexNo": 26,
    "category": "ねずみポケモン",
    "types": ["でんき", "エスパー"],
    "heightM": 0.7,
    "weightKg": 21.0,
    "stats": { "hp": 60, "attack": 85, "defense": 50, "spAttack": 95, "spDefense": 85, "speed": 110, "total": 485 },
    "flavorText": "（最新作の説明文）",
    "flavorTextGame": "（ソフト名）",
    "games": ["サン・ムーン", "..."],
    "generation": 7
  }
}
```

数値はイメージであり、実データはスクリプトの出力を正とする。

### 4.4 workConfig.json

```json
{
  "workId": "pokemon",
  "title": "ポケモン",
  "displayFields": [
    { "key": "dexNo", "label": "全国図鑑No", "format": "zeroPad4" },
    { "key": "category", "label": "分類" },
    { "key": "types", "label": "タイプ", "format": "badges" },
    { "key": "heightM", "label": "高さ", "unit": "m" },
    { "key": "weightKg", "label": "重さ", "unit": "kg" },
    { "key": "stats", "label": "種族値", "format": "statBars" },
    { "key": "flavorText", "label": "図鑑説明", "format": "longText" },
    { "key": "games", "label": "登場ソフト", "format": "chips" }
  ],
  "filters": [
    { "key": "generation", "label": "世代", "type": "multiSelect", "match": "any" },
    { "key": "types", "label": "タイプ", "type": "multiSelect", "match": "any" }
  ]
}
```

`format` は表示部品の種類で、画面側に部品（バッジ、棒グラフ、長文など）を用意しておく。項目の追加・並べ替えは設定ファイルの編集だけで済む。

## 5. データ生成スクリプト（buildItems.mjs）

PokeAPIから全種族と各フォルムを取得し、4章の形式の items.json を出力する。新ポケモン追加時に再実行するだけで更新できるようにする。

### 5.1 使用するPokeAPIのデータ

| エンドポイント | 取得する情報 |
| --- | --- |
| pokemon-species | 日本語名、分類（genera）、図鑑説明文、世代、フォルム一覧（varieties）、性別差の有無 |
| pokemon | タイプ、高さ、重さ、種族値、画像URL、登場ソフト（game\_indices） |
| pokemon-form | フォルムの日本語名、戦闘中のみか（is\_battle\_only）、メガシンカか、登場したバージョン |
| version / version-group | ソフトの日本語名、世代 |

日本語は `ja` を優先し、なければ `ja-Hrkt` を使う。高さは dm、重さは hg で返るため、どちらも10で割って m・kg に変換する。

### 5.2 フォルムの判定ルール

1. 種族の既定の姿を1件として登録する
2. varieties の各姿について、メガシンカ・キョダイマックス・戦闘中のみの姿は除外する
3. 残った姿のうち、既定の姿とタイプまたは種族値が異なるものは別の1件として登録する（リージョンフォーム等）
4. タイプ・種族値が同じ姿、1つの姿に属する見た目違い（アンノーンの文字、ビビヨンの模様等）、性別差のメス画像は、該当する1件の images に追加する
5. ぬしポケモンなど特殊な個体の扱いは、実装時に一覧を出して作成者が判断する

### 5.3 その他の判定

- **世代**：既定の姿は種族の世代。フォルムはそのフォルムが登場したバージョンの世代
- **画像**：Pokémon HOMEの画像（`sprites.other.home`）を使い、メスは `front_female`。欠けている場合はレポートに出し、代替を作成者と決める
- **図鑑説明文**：日本語の説明文のうち最も新しいソフトのもの1件と、そのソフト名
- **登場ソフト**：game\_indices は新しい作品の情報が欠けやすいため、図鑑説明文が存在するソフトと合算する。それでも欠ける場合の補完方法は実装時に判断する

### 5.4 動作上の注意

- リクエストは数千件になるため、取得結果をローカルにキャッシュし、間隔を空けて順に取得する（PokeAPIの利用マナー）。キャッシュはリポジトリにコミットしない
- PokeAPIに最新の種族がまだ無い場合は、手入力の補完ファイル（manualItems.json）をマージできるようにする
- 実行後に検証レポートを出力する：種族数（1028件あるか）、総件数、画像・日本語文の欠け、除外したフォルム一覧

## 6. 画面仕様

画面は1枚で、「待機中」「抽選中」「結果表示」の3状態を切り替える。片手で操作できるよう、主ボタンは画面下部に置く。

### 6.1 レイアウト（縦長スマホ）

1. **ヘッダー**：アプリ名、絞り込みボタン、現在の対象件数（例：対象 312件）
2. **画像エリア**：画面中央。結果表示時は見た目違いの数だけドットを表示
3. **詳細エリア**：結果表示時のみ。名前・フォルム名の下に workConfig.json の displayFields を順に表示し、縦スクロールで読む
4. **主ボタン**：画面下部に固定。状態に応じて START／STOP に切り替わる

### 6.2 状態ごとの動き

| 状態 | 画像エリア | 主ボタン | 押したとき |
| --- | --- | --- | --- |
| 待機中 | 「？」のプレースホルダー | START | 抽選中へ |
| 抽選中 | シルエットが高速で切り替わる | STOP | 減速して結果表示へ |
| 結果表示 | カラー画像＋詳細 | START | 詳細を閉じて抽選中へ |

### 6.3 抽選演出（シルエットシャッフル案）

- 抽選中は画像を黒いシルエット（CSSの `filter: brightness(0)`）で表示し、約80ミリ秒ごとに入れ替える
- 入れ替えに使うのは、絞り込み後の対象から無作為に選んで先読みした30件程度。全件の画像を読み込まないことで通信量と表示遅れを抑える
- STOPを押した瞬間に対象全体から均等な確率で1件を決定し、その画像の読み込みを始める
- 約1秒かけて入れ替え間隔を伸ばして減速し、最後に決定した1件のシルエットで止めてからカラーに切り替えて詳細を表示する
- 演出は「探している感」が伝わることが目的。実装後に見て調整する前提とする

### 6.4 見た目違いの切り替え

- 画像の左右スワイプ、または画像タップで images の次の画像へ切り替える
- 画像の下に現在のラベル（例：メス、Aの文字）とドットを表示する
- 見た目違いが無い場合はドットを出さない

### 6.5 表示部品（format）

| format | 表示 |
| --- | --- |
| zeroPad4 | 4桁ゼロ埋め（No.0026） |
| badges | タイプごとに色分けしたバッジ |
| statBars | 6項目の数値と横棒グラフ、合計値 |
| longText | 折り返し表示の長文。出典ソフト名を小さく添える |
| chips | 小さなタグを並べる。多い場合は折りたたみ |
| 指定なし | 値をそのまま表示（unit があれば付ける） |

## 7. 絞り込み機能

絞り込みは workConfig.json の filters で定義し、画面は定義に従って部品を自動生成する。新しい絞り込み項目は、設定ファイルへの1行追加（必要なら新しい type の部品追加）で増やせる。

### 7.1 判定ルール

- 同じ項目の中で複数選択した場合は「いずれかに当てはまる」（OR）
- 異なる項目の間は「すべてに当てはまる」（AND）
- 例：世代に第1・第2、タイプにみずを選ぶ → 「第1世代または第2世代」かつ「みずタイプを含む」
- 何も選んでいない項目は条件なし
- 項目ごとに `match` を `all` にすると「すべて含む」判定になる（例：みず かつ ひこうを両方持つ）。v1の既定は `any`

### 7.2 画面

- ヘッダーの絞り込みボタンで、下から引き出すパネルを開く
- 項目ごとに選択肢をタップで選ぶチップとして並べる（世代：第1〜第9、タイプ：18種）
- パネル内に該当件数をリアルタイムで表示し、「クリア」「適用」ボタンを置く
- 該当0件のときは適用できないようにし、STARTも押せなくする
- 選択状態はブラウザ内に保存し、次回起動時に復元する（保存キーは9章のルールに従う）

### 7.3 filters の type（拡張用）

| type | 用途 | v1 |
| --- | --- | --- |
| multiSelect | 決まった選択肢から複数選ぶ（世代、タイプ） | 実装する |
| range | 数値の範囲（例：種族値合計、重さ） | 将来 |
| text | 名前の部分一致 | 将来 |

選択肢の一覧は設定ファイルに書くか、未指定なら items.json の実際の値から自動で作る。

## 8. 他作品対応の方針

他作品の追加は「works/ にフォルダを1つ足すこと」で完結させ、画面のコード変更は新しい表示部品が必要な場合だけにする。

### 8.1 作品一覧と切り替え

- `works/workList.json` に作品のID・表示名・並び順を持つ
- 作品が2つ以上になったらヘッダーに作品切り替えを表示する（v1は1作品のため非表示）
- 絞り込みの保存も作品ごとに分ける

### 8.2 追加手順

1. `works/<作品ID>/` を作り、workConfig.json に表示項目と絞り込み項目を定義する
2. items.json を4.1の共通構造で用意する
3. workList.json に作品を追加する

### 8.3 ONE PIECEを追加する場合の想定

- PokeAPIのような公開データが無いため、スプレッドシート等で手作りしたCSVを items.json に変換するスクリプト（`scripts/onePiece/buildItems.mjs`）を用意する
- 属性の例：懸賞金、所属（海賊団など）、悪魔の実、初登場話。確定は追加時に決める
- 画像の入手元が無いことが最大の課題。画像なしで名前だけ表示する、自分で用意した画像を使うなど、追加時に方針を決める

## 9. 非機能要件・注意事項

個人用ツールとして「無料・軽快・目立たない」を優先する。

| 観点 | 方針 |
| --- | --- |
| 費用 | 0円（GitHub Pages、PokeAPIとも無料） |
| 公開範囲 | URLを知る人は閲覧可能。`<meta name="robots" content="noindex, nofollow">` を入れ、他のページからリンクしない。リポジトリも公開になる点を了承済み |
| 著作権 | 画像はリポジトリに保存せずPokeAPIのURLを参照する。個人利用に留め、SNS等での公開や共有はしない |
| 表示速度 | items.json は起動時に1回だけ読み込む。画像は表示する分だけ読み込み、全件の先読みはしない |
| 外部依存 | 画像とデータの元はPokeAPI（およびその画像リポジトリ）。配信が止まった場合は画像が出なくなるため、そのときに対策を検討する |
| パス | サブフォルダ（/RandomDex/）で公開されるため、ファイル参照はすべて相対パスで書く |
| 保存キー | 同じドメインの他アプリ（カラオケ得点管理）と保存領域を共有するため、ブラウザ保存のキーは必ず `R``andomDex_` で始める |
| 対応ブラウザ | スマホのSafari・Chromeの最新版。PCは表示崩れしない程度 |

## 10. 開発の進め方と今後の検討事項

この設計書をリポジトリの `docs/designDoc.md` として置き、Claude Codeに段階ごとに依頼する。各段階の終わりに作成者が動作を確認してから次へ進む。

### 10.1 実装ステップ

- [ ] ステップ1：GitHubに RandomDex リポジトリを作成し、Pagesを有効化。空の index.html が `carrot-99.github.io/``R``andomDex/` で表示されることを確認
- [ ] ステップ2：buildItems.mjs を作成・実行し、検証レポートを確認。除外フォルムやぬしポケモン等の扱いを作成者が判断
- [ ] ステップ3：items.json を読み込み、START／STOPで抽選して結果を表示する最小版
- [ ] ステップ4：workConfig.json に従った詳細表示（バッジ、種族値の棒グラフ等）
- [ ] ステップ5：シルエットシャッフル演出と見た目違いのスワイプ切り替え
- [ ] ステップ6：絞り込み（世代・タイプ）と選択状態の保存
- [ ] ステップ7：スマホ実機で確認し、演出の速さや見た目を調整

### 10.2 今後の検討事項
